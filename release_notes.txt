2026-08-15 - Input isolation & held-key investigation
-------------------------------------------------------------------------------
Branch: usr/mr5/input-isolation

FOCUS
  Reported problem: holding certain keys prevents other keys from sounding;
  the blocking is partial and inconsistent (only some keys, not always).

ROOT CAUSE (main symptom)
  Keyboard GHOSTING / rollover - a HARDWARE limit, not a bug in this program.
  On most membrane/laptop keyboards, keys share rows/columns in a wiring
  matrix, so certain simultaneous combinations physically cannot be reported to
  the computer. The current event-driven input path (per-keycode tracking in
  pressed_kc) is correct and does not block notes on its own. Documented in
  README.md ("Input Isolation & Held-Key Issues") and TROUBLESHOOTING.md.
  Software cannot override a hardware matrix limit; an NKRO/6KRO keyboard is
  the real fix.

  Context from history: an earlier attempt at OS-level key control (the
  `keyboard`-library KeyboardBlocker, commits bc2cbda/7611c45) was removed in
  e078738 - it required admin rights and used a fragile global hook. Today's
  change is the lighter-weight successor: an SDL keyboard grab that needs no
  admin and releases automatically on focus loss.

SOFTWARE CHANGES (the "cut off macros / keyboard rules" request)
  * Disabled OS keyboard auto-repeat via pygame.key.set_repeat(0). One physical
    press now yields one note-on instead of a stream of synthetic repeats that
    could crowd out other keys.
  * Added keyboard grab while the window is focused. New helper
    PianoApp._set_input_grab() calls pygame.event.set_keyboard_grab() (with
    set_grab() as a fallback) so macros, remappers, and global hotkeys are far
    less able to intercept keys during play. Version-safe via hasattr guards.
    No admin rights required (unlike the old KeyboardBlocker).
  * Grab releases automatically on focus loss / minimize, re-applies on focus
    gain, and releases on app exit (__exit__), so it never locks up the system.

BUG FIXES
  * Fixed broken focus-loss detection that shipped in e078738. The check
    `event.type == getattr(pygame, 'WINDOWFOCUSLOST', None)` compared event.type
    against None on pygame builds lacking that constant (so it never matched)
    and never handled focus GAIN. Rewritten with safe sentinel lookups for
    WINDOWFOCUSLOST / WINDOWFOCUSGAINED / WINDOWMINIMIZED: flush held notes and
    drop the grab on loss/minimize, re-grab on gain.
  * Keyboard.spec: fixed the entry-point/icon casing regression introduced in
    a2cb583. Restored 'Keyboard.py' (was reverted to 'keyboard.py') and set the
    icon to 'icon.ico' (was 'Icon.ico'). Casing mismatches broke builds on
    case-sensitive setups.

DOCUMENTATION
  * README.md rewritten: added Input Isolation & Held-Key Issues section,
    corrected run command to `python Keyboard.py`, corrected supported range
    wording (C1-C8 / MIDI 24-108), completed the controls table (F11 reset,
    F12 learn, keys 5-9), noted reserved keys.
  * Added TROUBLESHOOTING.md focused on the ghosting question with a self-test.

FILES CHANGED
  Keyboard.py, Keyboard.spec, README.md, release_notes.txt (new),
  TROUBLESHOOTING.md (new)

NOTES / NEXT IDEAS (not yet implemented)
  * Optional on-screen "keys currently held" counter to visualize the rollover
    ceiling.
  * Optional toggle to disable the keyboard grab for users who want global
    hotkeys active while playing.

2025-12-15 08:02  3113faa  Keycode remapping + event-driven input (final of day)
-------------------------------------------------------------------------------
  The largest and most significant pre-existing change. Two big things:
  * Replaced per-frame POLLING (_scan_notes reading key.get_pressed each frame)
    with EVENT-DRIVEN input: handle_note_on_kc / handle_note_off_kc driven by
    pygame KEYDOWN / KEYUP. This is the current input architecture.
  * Added a REMAPPABLE KEYMAP system keyed by keycode (not character):
    DEFAULT_KC_TO_MIDI, load_user_keymap / save_user_keymap backed by
    keymap.json, a RESERVED_KC set, live "mapping mode" (F12 to learn, F11 to
    reset), and key labels drawn from pygame.key.name().
